Run these commands from this folder in a Linux/Ubuntu terminal.
Required tools: Flex, Bison (yacc), and GCC.

yacc -d parser.y
lex lexer.l
gcc y.tab.c lex.yy.c -o compiler

Paste the complete demo command below:
./compiler <<'EOF'
for (i = 0; i < n * 4; i = i + 1)
{
    r = 16 * 5;
    s = x * y + z;
    t = i + s;
}
EOF

The update can also be i++ or i = i + 2, and similarly for another counter.
Its variable must match the variable on the left of the condition.

The output is tokens, syntax status, original TAC, optimized TAC,
and target code for the same simple teaching machine as the while version.
This compiler prints code; it does not execute the input program.

For interactive input, run ./compiler, paste the program, then press Ctrl+D.
The parser accepts one construct, braces and a nonempty assignment list.
Names use lowercase letters. Expressions support numbers, +, -, *, and
parentheses. The comparison is <. There are no declarations or nested
control statements. Fixed arrays are for these short exam inputs.

Initialization is emitted before L1 and runs once. The header update is
remembered while parsing and emitted AFTER the body. It must not execute
before the first body statement. The entry guard preserves zero iterations.

Code-motion scope: an unchanged right-hand bound, one assignment to each
body result, and results used after their definitions. Update the counter
only in the for header. Body expressions that depend on it stay in the loop.
For n=1, x=2, y=3, z=4, the demo runs for i=0,1,2,3 and ends with
i=4, r=80, s=10, t=13. If n=0, initialization still sets i=0 and
r, s and t retain their previous values.
